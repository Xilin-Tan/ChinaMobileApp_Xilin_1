# 技术决策

> 最后更新：2026-11-18

## D1. 主流程不用大模型

**决定**：CSV → 报表 全链路是确定性代码，不调用任何模型。

**理由**：结构固定，规则可枚举。用模型会带来延迟、成本、不确定性。

**例外**：可在报表末尾追加一段"本期数据解读"文字，作为可选功能，失败不影响主流程。

## D2. 模板用配置描述，不写死在代码里

**决定**：用一个配置文件（JSON/YAML）声明：哪些列 → 哪些指标 → 什么图表 → 放哪个位置。

**理由**：报表结构微调时改配置即可，不需要改代码、不需要重新发版。
配置文件同时是"报表长什么样"的唯一真相来源，需要版本管理。

## D3. 引擎与界面分层

**决定**：

```
core/     解析、校验、计算、渲染 —— 纯逻辑，不依赖任何 UI
shell/    桌面壳、网页壳、手机壳 —— 只负责交互和展示
```

**理由**：今天做 Windows 版、以后做手机版，引擎一行都不用重写。

## D4. 平台路线：桌面优先 → 手机按需

| 阶段 | 内容 | 说明 |
|---|---|---|
| 1 | Windows 桌面版 | 主战场，先跑通 |
| 2 | 手机查看 | 推 PDF/图片到企业微信，零开发 |
| 3 | 手机生成 | 网页 + 添加到主屏幕（PWA） |

**iOS 的现实约束（重要）**：

- Windows 上**无法编译** iOS 应用，必须有 Mac 或云 Mac
- 免费 Apple ID 签名的包 **7 天失效**，需要重签
- 上架 App Store 需 $99/年 + 审核
- 因此：PWA 是"自己用 + iOS"最划算的路径

**Android**：可以自行打包 APK 安装，免费无限制。

## D5. 存储与回溯

**决定**：每次处理都归档「输入文件 + 输出结果 + 使用的模板版本」。

**理由**：报表数字被质疑时能还原当时的计算依据。

## 尚未决定

- 输出格式的优先级：PDF / Excel / 图片，哪个是主要交付形态
