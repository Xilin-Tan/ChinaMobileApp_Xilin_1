## Q1. 企业微信里的报表，流向是哪个方向？ ✅ 已确认

- [x] **别人发给你，你来处理**（2026-11-19 确认）

**结论**：只需要"输入 + 计算"，**不需要群机器人推送**。

重要发现：企业微信会把收到的文件自动落盘到固定目录

```
%APPDATA%\Tencent\xwechat\xwechat_files\<wxid>\msg\file\<yyyy-MM>\
```

软件可以直接扫描这个目录，省掉手动找文件/拖拽。
### 补充：怎么判断"最新一份"（2026-11-19 实测）

**文件名序号和时间先后无关，修改时间也不可信。**

实测证据：

```
网格正向销售完成情况日预测通报(12).xlsx → 通报 2026-11-19 13:45
网格正向销售完成情况日预测通报(11).xlsx → 通报 2026-11-19 17:15   ← 才是最新
```

而且这个目录里当天所有 xlsx 的 `LastWriteTime` 都是 `19:43`（企业微信批量重写了一遍），
按文件时间取最新会**选到过期报表**，且不会报错。

**唯一可靠依据：读文件内容里的「通报时间」。**

- 位置：`auto` 工作表里、表头叫「通报时间」的那一列的第 2 行
- 列位置会随模板变（见过 `AP` / `AR` / `AY` / `BB`），**不能写死**
- 稳妥取法：读「通报」表 `A1` 的公式，形如 `"标题"&" "&auto!AP5`，顺着它去 `auto` 表取那个格子
- 不是 `inlineStr` 就是共享字符串（老文件 `t="s"`，值是索引），两种都要认

实现：`app/Inbox.cs` → `ProbeReportTime` / `ProbeTimes` / `LatestPerKind`。
只用正则定位、不建整表模型，**实测 22 份共 228 ms，平均 10 ms/份**。

选最新时：可比通报时间就比通报时间；读不到才退回修改时间（并在界面上标出来）。

**已验证**：扫本机企业微信目录，网格类正确选中 `(11)`（11-19 17:15）而非 `(12)`；
三份报表跑完整流程全部成功（区县 187 ms / 网格 6.4 s / 重点业务 643 ms）。
